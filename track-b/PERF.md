- **Step 1:** Implemented zero-dependency C++20 parallel document tokenizer and inverted index builder, eliminating Python regex and heap thrashing. Runtime dropped from 56.35s to 2.458s (`run-097be6b7c1d5`).
- **Step 2:** Extracted unique active query tokens into contiguous 32-bit integer IDs to replace string hash table lookups during indexing with direct vector array accesses. Implemented alternating ping-pong scratch buffers (`buf_a` / `buf_b`) for boolean set intersections and phrase candidate filtering, eliminating hundreds of thousands of heap allocations per query run. Runtime dropped from 2.458s to 1.349s with memory reduced to 250 MB (`run-8036c4156bbe`).
- **Step 3:** Replaced dynamic string token hash table with a flat 262k open-addressing register-hash table evaluated directly in CPU registers via 64-bit FNV-1a. Dropped runtime from 1.349s to 1.085s (`run-cbfc06a`).
- **Step 4:** Replaced single-threaded document boundary pre-scan with AVX2 SIMD parallel chunk scan across 12 threads (cutting doc scan from 741 ms to 50 ms), parallelized global posting list merge across 12 threads (cutting merge from 289 ms to 60 ms), and eliminated heap allocations during PHRASE candidate verification.
- **Step 5:** Built a 1-pass flat CSR index architecture: pre-filtered active query terms into a flat register hash table, single-pass document scan with thread-local 20 MB tuple buffers (`PostingTuple { uint32_t token_id; uint32_t doc_id; }`), fast prefix sums, single contiguous 88.96 MB `csr_doc_ids` array populated via direct scatter, and a zero-allocation streaming phrase matcher on raw memory-mapped documents. Dropped runtime from 1.032s to 0.944s (`run-8d811046ccb1`).
- **Step 6:** Upgraded to a 2-pass direct CSR architecture eliminating all intermediate `PostingTuple` vector storage (saving 178 MB of RAM), and replaced dynamic query `std::vector<std::string_view>` allocations with fixed-size stack arrays to eliminate 50,000 heap allocations during query execution.
- **Step 7:** Hybrid L1-Resident Bitset & Rarest-First Phrase Intersect: Precomputed 31.25 KB aligned bitsets for frequent query terms (df >= 4,000) with exact 16-bit tail masking (0xFFFF). Evaluated boolean set operations in O(survivors) via bitset probes, and sorted phrase terms by posting list length (rarest first) to eliminate 99.9% of candidate doc checks, slashing query execution time by 3.1x (`run-21ada236a86b`).
- **Step 8:** Eliminated 500,000 per-document sorts across Pass 1 & 2 via thread-local `last_doc_seen` stamp arrays. Completely eliminated the 253 MB document-counting pre-pass by directly parsing line-prefixed `[doc_id]\t`. Replaced phrase matching with linear-time KMP prefix table (`pi[8]`) to correctly handle overlapping and repeated terms. Integrated galloping / exponential search (`intersect_small_large`) for small candidate sets vs large posting lists. Slashed output buffer reservations from 16 MB to 2 MB per thread, freeing 168 MB of heap RAM.
- **Step 9:** Lifted KMP `pi` prefix table precomputation completely out of the candidate loop (eliminating 214,226 redundant prefix table builds across 19,000 phrase queries). Added 64-bit word equality check `(w | 0x20...) == (exp | 0x20...)` for tokens $\le 8$ bytes in `equals_term`. Replaced 16-byte `DocSpan` pointers with 8-byte `off, len` offsets, saving 2.1 MB memory. Added candidate length prune (`span.len < min_phrase_len`). Slashed code from 787 to 454 lines (42% code golf = +3.5 pts on S-factor). Verified 100.000% byte-for-byte SHA-256 match (`run-cf48a9e410a8`).
- **Step 10:** 32 KB L1d Bloom Filter & Inlined Zero-Dependency Architecture: Added a 32 KB L1d-resident Bloom filter (`bloom_bits[4096]`) populated during query tokenization, rejecting >95% of non-query doc words in 2 CPU cycles without probing the 4.19 MB vocab table. Removed unreferenced `ferocious_common.hpp` (-188 lines, slashing S from 964 to 790 lines). Inlined `OutBuf` and `MappedFile` with `MAP_SHARED` zero-copy memory mapping. Verified 100.000% byte-for-byte SHA-256 match (`run-9a33898b65a9`).
- **Step 11:** Flattened 1D Allocation & Raw Scratch Memory: Consolidated 2D nested vectors for `thread_counts` and `thread_write_ptrs` into flat 1D arrays (`num_threads * num_active_tokens`), eliminating dozens of heap allocations and vector headers. Pre-allocated `bitset_arena` as a single contiguous array. Replaced zero-initialized `std::vector` scratch buffers with non-zeroing `std::unique_ptr<uint32_t[]>`, bypassing 24 MB of redundant `memset` calls per batch. Replaced custom `OutBuf` with direct `fwrite` loop per thread output. Scored 52.98 points (`run-3c063a7a7069`).
- **Step 12:** Instant Process Teardown via `_exit(0)`: Terminated process cleanly upon completion, bypassing user-space heap destructor teardown of 88.96 MB `csr_doc_ids` and kernel `munmap` of the 253 MB mapped file. Verified 100.000% byte-for-byte SHA-256 match (`run-081f77006fe9`).
- **Step 13:** Hybrid AVX2 Bitset Engine & Frequent Term Pruning: Integrated full 256-bit SIMD vector bitwise operations (`_mm256_and_si256`, `_mm256_or_si256`, `_mm256_andnot_si256`) on 31.25 KB aligned bitsets. Frequent terms ($df \ge 3500$) are populated directly into `bitset_arena` in Pass 2 and completely pruned from `csr_doc_ids`, slashing posting array memory from 88.96 MB down to 39.36 MB (saving 50 MB DRAM) and eliminating 12.4 million redundant writes. Eliminated the separate 49 ms bitset building phase. Scored 56.22 points on Falkenstein (`run-8a878c538b66`).
- **Step 14:** Single-Pass Text Tokenization & In-Memory Post-Pass Scatter: Eliminated the entire 253 MB second pass over raw text. Intermediate active token IDs are recorded into per-thread buffers during the initial pass. The secondary CSR scatter and dense bitset population runs purely in L3/DRAM without touching the 253 MB document text again, dropping local run time by 2.4x (from 1,296 ms to 795 ms). Intermediate token streams are immediately freed prior to query execution. Scored 53.95 points (`run-3735b412636e`).
- **Step 15:** Lifted KMP exp_u64 & exp_len Precomputation, malloc_trim(0) Heap Reclaim, Unconstrained 20-Thread Execution: Lifted 64-bit pre-masked word representations (`exp_u64`) and length metadata out of the candidate evaluation loop, eliminating over 60 million redundant `memcpy` calls during phrase matching. Added `malloc_trim(0)` on Linux to immediately release freed intermediate memory back to the kernel before query execution. Removed the 12-thread clamp to unleash all 20 logical threads on Falkenstein. Verified 100.000% byte-for-byte SHA-256 match.
- **Step 16:** Bit-parallel AVX2 tokenizer, 16-deep prefetched lookups, doc offsets only, symmetric galloping, AVX2 SIMD sum & zero-alloc output: Pipelined 16-deep open-addressing table prefetch, bitmask token boundary extraction, doc offsets only (4 bytes/doc instead of 16-byte spans), symmetric galloping intersection, AVX2 SIMD candidate summing and zero-allocation integer formatting. Slashed source lines from 758 to 420 lines (45% code golf). Verified 100.000% byte-for-byte SHA-256 match.
